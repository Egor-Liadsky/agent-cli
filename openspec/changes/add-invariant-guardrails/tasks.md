## 3. `InvariantGuard` — выходная политика

- [x] 3.1 Реализовать `InvariantGuard: OutputPolicy` в `pipeline.rs`
      (или отдельном модуле `invariants.rs`): служебный запрос к переданному
      `Agent` с промптом, перечисляющим активные инварианты и ответ модели,
      разбор структурированного вердикта (нарушен инвариант / не нарушен +
      id нарушенного).
- [x] 3.2 На нарушение возвращать `PolicyOutcome::reject("invariant_violation",
      reason)` с текстом, называющим id и `statement` нарушенного инварианта,

      `RejectOutput` в `pipeline.rs`).
- [x] 3.3 Покрыть тестом, что при пустом `InvariantSet` `InvariantGuard` не
      выполняет служебный вызов к агенту вообще (проверка счётчика вызовов
      `FakeAgent`, как в `judge_uses_the_same_agent`).
- [x] 3.4 Покрыть тестом, что код отказа `invariant_violation` отличается от
      кодов отказа входных политик, и что `PolicyLog` содержит запись стадии
      `InvariantGuard` в `output`, а не в `input`.
- [x] 3.5 Зарегистрировать `InvariantGuard` в списке выходных политик по
      умолчанию для потребителей `agentcore` (`agentcli` и `agentd`) и
      проверить, что регистрация не ломает существующий набор политик при
      пустом `InvariantSet`.
