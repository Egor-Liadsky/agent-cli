## Purpose

Позволяет каждому чату клиента сужать операторский лимит контекстного окна
сервиса `agentd` своим собственным значением, а не одним общим лимитом на
весь клиент.

## ADDED Requirements

### Requirement: Лимит контекста — настройка конкретного чата

`ChatSettings` (общий тип ядра) SHALL содержать необязательное поле
`max_context_tokens` — целое положительное число токенов, лимит контекста
именно этого чата. Не заданное поле SHALL означать, что чат не сужает лимит
контекстного окна: запросы для этого чата уходят без поля
`settings.max_context_tokens`, и действует операторский лимит `agentd` по
умолчанию (либо лимит, унаследованный от сохранённых настроек чата на
сервере — см. Requirement «Лимит контекста передаётся в запрос к сервису»).
Значение конкретного чата не зависит от значений других чатов клиента.

#### Scenario: У чата без заданного лимита

- **WHEN** у чата не задано `max_context_tokens`
- **THEN** запросы этого чата к сервису не содержат поле
  `settings.max_context_tokens`, если только запрос не переопределяет его
  разово

#### Scenario: У разных чатов разные лимиты

- **WHEN** у чата A задан `max_context_tokens = 4000`, а у чата B —
  `max_context_tokens = 16000`
- **THEN** запросы чата A уходят с `settings.max_context_tokens: 4000`,
  запросы чата B — с `settings.max_context_tokens: 16000`, независимо от
  порядка обращения к чатам

### Requirement: Конфиг клиента задаёт лимит контекста по умолчанию для новых чатов

`Config` SHALL содержать необязательное поле `max_context_tokens` — лимит
контекста по умолчанию для новых чатов, той же формы, что `Config.model`.
При создании нового чата клиент SHALL скопировать это значение в
`ChatSettings.max_context_tokens` нового чата. Дальнейшие изменения
`Config.max_context_tokens` не влияют на уже созданные чаты — как и для
`Config.model`. Значение сохраняется в файле конфигурации и переживает
перезапуск клиента.

#### Scenario: Новый чат наследует умолчание из конфига

- **WHEN** в конфиге клиента задан `max_context_tokens = 4000` и пользователь
  создаёт новый чат
- **THEN** у нового чата `ChatSettings.max_context_tokens` равен `4000`

#### Scenario: Изменение умолчания не затрагивает существующие чаты

- **WHEN** пользователь меняет `Config.max_context_tokens` после того, как
  чат уже создан
- **THEN** лимит контекста уже существующего чата не меняется

### Requirement: Лимит контекста чата передаётся в запрос к сервису

Когда у чата задан `ChatSettings.max_context_tokens`, клиент SHALL
передавать его в поле `settings.max_context_tokens` тела `POST /v1/chat` для
каждого запроса этого чата — как разового (`ask`), так и в существующем чате
(`ask_in_chat`). Клиент MUST NOT проверять значение сам или сравнивать его с
операторским лимитом сервиса — эта проверка принадлежит `agentd`; ответ
сервиса (`400 context_limit_invalid` при значении больше операторского
лимита, `400 context_limit_exceeded` при истории больше эффективного лимита)
показывается пользователю как обычная ошибка запроса.

#### Scenario: Лимит уходит в каждый запрос этого чата

- **WHEN** у чата задан `ChatSettings.max_context_tokens` равный N
- **THEN** тело каждого `POST /v1/chat` для этого чата содержит
  `settings.max_context_tokens: N`

#### Scenario: Сервис отклоняет лимит или историю

- **WHEN** сервис отвечает `400` с кодом `context_limit_invalid` или
  `context_limit_exceeded`
- **THEN** клиент показывает пользователю текст ошибки сервиса, не отправляя
  запрос повторно и не изменяя сохранённый лимит контекста чата

### Requirement: Лимит контекста настраивается командой и в интерактивном режиме

Клиент SHALL предоставлять команду `agentcli config context-limit` с
действиями `set <tokens>` (сохранить умолчание для новых чатов), `clear`
(снять умолчание) и `show` (показать текущее умолчание) —
`Config.max_context_tokens`, по аналогии с `config set-model`. Интерактивный
режим (TUI) SHALL позволять посмотреть и изменить лимит контекста ТЕКУЩЕГО
чата в панели настроек, рядом с полем модели, и сохранить его в настройки
именно этого чата (`PATCH /v1/chats/{id}`) — не в глобальный конфиг. Пустое
поле в TUI SHALL сбрасывать лимит чата. Введённое значение, не являющееся
положительным целым числом, SHALL быть отклонено с понятным сообщением —
командой или в TUI, — а прежнее сохранённое значение остаётся без изменений.

#### Scenario: Команда сохраняет умолчание для новых чатов

- **WHEN** пользователь выполняет `agentcli config context-limit set 4000`
- **THEN** значение сохраняется в `Config.max_context_tokens` и применяется
  к чатам, создаваемым после этого

#### Scenario: Команда снимает умолчание

- **WHEN** пользователь выполняет `agentcli config context-limit clear`
- **THEN** `Config.max_context_tokens` становится не заданным

#### Scenario: Пользователь задаёт лимит текущего чата в TUI

- **WHEN** пользователь вводит положительное целое число в поле лимита
  контекста панели настроек и подтверждает сохранение
- **THEN** значение сохраняется в `ChatSettings.max_context_tokens` этого
  чата и используется в его следующих запросах, а другие чаты не меняются

#### Scenario: Некорректный ввод

- **WHEN** пользователь передаёт нечисловое значение или ноль команде
  `config context-limit set` либо вводит их в поле лимита контекста TUI
- **THEN** клиент показывает сообщение об ошибке и не изменяет сохранённое
  значение
