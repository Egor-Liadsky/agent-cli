## Context

Редактор настроек (`SettingsEditor` в `crates/cli/src/tui.rs`) держит
значения полей строками; `handle_settings_key` получает только состояние и
канал событий, без доступа к `Terminal`. Терминал принадлежит `run_app`,
который крутит цикл `tokio::select!` поверх `EventStream` crossterm. Процесс
запущен `#[tokio::main]`: будущее `run_app` исполняется через `block_on` в
главном потоке, фоновые задачи — на рабочих потоках.

Поля-каталоги для MCP-серверов в TUI:

| Поле            | Раздел              | Хранение                         |
|-----------------|---------------------|----------------------------------|
| `ActivityRoot`  | «Сводки активности» | `Config::activity_root`          |
| `GitRepository` | инструменты         | `ChatSettings::git_repository`   |

`pipeline_root` и `pipeline_output` в TUI не редактируются (только
`agentcli config pipeline`), поэтому в изменение не входят.

Занятые клавиши в режиме настроек. До `handle_settings_key` событие
перехватывают глобальные обработчики: `Ctrl+C`, `Ctrl+Y`, `Ctrl+E`, `Ctrl+U`,
`Ctrl+R`, `Ctrl+O` (импорт контекста), `Ctrl+P` (закрыть настройки),
`Ctrl+F` (факты), `Ctrl+B`, `Ctrl+K`, `Ctrl+T`, `Ctrl+A`/`Ctrl+Ф`. Внутри
настроек: `Ctrl+S`, `Ctrl+D`, `Ctrl+L`, `Esc`, `Tab`, стрелки, `Enter`,
пробел, `Backspace`, печатные символы.

## Goals / Non-Goals

**Goals:**
- Нативный диалог выбора папки для `ActivityRoot` и `GitRepository`.
- Корректные приостановка и восстановление терминала.
- Понятное поведение без графической сессии и при отмене.

**Non-Goals:**
- Диалог для `pipeline_root`/`pipeline_output` и подкоманд `config`.
- Выбор файлов (не каталогов), история недавних путей.

## Decisions

**Клавиша `Ctrl+X` (ещё `Ctrl+Ч` на русской раскладке).** Первый кандидат,
`Ctrl+O` («открыть»), в режиме настроек занят: глобальный обработчик импорта
контекста поглощает его раньше `handle_settings_key`. `Ctrl+F` («folder»)
занят экраном фактов так же. `Ctrl+X` нигде не используется; `Ctrl+H`,
`Ctrl+I`, `Ctrl+J`, `Ctrl+M` отпадают — терминал шлёт их как `Backspace`,
`Tab` и `Enter`. `Ctrl+Z`/`Ctrl+Q` отпадают из-за ассоциаций с
приостановкой процесса и XON.

**`rfd` без фич по умолчанию, с `xdg-portal`.** `rfd` даёт один API на
macOS (NSOpenPanel), Windows и Linux. Фичи по умолчанию тянут Wayland-
клиент, а `gtk3` — системные библиотеки GTK для сборки; портал XDG через
D-Bus не требует ничего при сборке и работает в любом современном
рабочем окружении. Альтернатива `osascript -e 'choose folder'` покрывает
только macOS.

**Отложенный запрос вместо вызова из обработчика клавиши.**
`handle_settings_key` лишь кладёт в `AppState::folder_pick` поле, для
которого нужен диалог. `run_app` после обработки пачки событий видит
запрос и вызывает `pick_folder_for_field`, где есть `&mut Terminal`. Так
не нужно протаскивать терминал через всю цепочку обработчиков.

**Главный поток, синхронный вызов.** AppKit требует, чтобы окно открывалось
из главного потока; `run_app` исполняется в главном потоке, поэтому
синхронный `FileDialog::pick_folder` зовётся прямо из цикла, без
`tokio::spawn`/`spawn_blocking` (они унесли бы вызов на рабочий поток).
Цикл при этом стоит — это и нужно: TUI скрыт, пока открыт модальный диалог.
Фоновые задачи (ответы модели, опрос демона) продолжают работать на
рабочих потоках и копятся в канале.

**Приостановка терминала.** Перед диалогом: `disable_raw_mode`,
`DisableMouseCapture`, `DisableBracketedPaste`, `LeaveAlternateScreen`,
показать курсор — как в `run` при выходе. После: обратная
последовательность и `terminal.clear()` для полной перерисовки. Нажатия,
попавшие в терминал, пока он был в обычном режиме, отбрасываются: они
адресовались не TUI. Восстановление выполняется и при ошибке диалога.

**Без графической сессии.** `rfd::FileDialog::pick_folder` возвращает
`Option` и не различает отмену и сбой, а над SSH на macOS панель открылась
бы на экране удалённой машины или не открылась вовсе. Поэтому до вызова
проверяется окружение (`gui_unavailable_reason`): сеанс SSH (`SSH_CONNECTION`
или `SSH_TTY`) или Linux без `DISPLAY` и `WAYLAND_DISPLAY` — диалог не
открывается, а строка статуса предлагает ввести путь вручную. Паника внутри
`rfd` ловится `catch_unwind` и превращается в ошибку. Проверка — функция
над явно переданными переменными, чтобы тестироваться без GUI.

**Путь в поле.** Выбранный путь записывается в поле как есть (абсолютный).
Путь не в UTF-8 не записывается: поле строковое и конфиг TOML, — вместо
этого сообщение в статусе.

## Risks / Trade-offs

- [Портал XDG отсутствует на Linux] → `rfd` вернёт `None`, пользователь
  увидит «каталог не выбран»; ручной ввод остаётся.
- [Цикл TUI стоит, пока открыт диалог] → ожидаемо для модального окна;
  события фоновых задач обрабатываются после возврата.
- [Эвристика SSH ложно срабатывает при X11-форвардинге] → на Linux с
  `DISPLAY` через SSH диалог тоже не открывается; принимаем ради
  предсказуемости, ручной ввод доступен.
