## Why

Ядро проекта (вызов модели, настройки чата, разбор ответа и телеметрия) сегодня
доступно только через TUI/CLI на машине пользователя: логика зашита в один
бинарный крейт `agentcli`, а конфигурация читается из `~/.config/agentcli/config.toml`.
Из-за этого нельзя обратиться к агенту по сети, нельзя держать ключ провайдера
на сервере, а не у клиента, и негде разместить будущие стадии контроля
(input-политики, output-политики, LLM-judge).

Нужен HTTP-сервис `agentd`, который принимает промпт по HTTP, прогоняет его
через явный конвейер обработки, вызывает модель по ключу, принадлежащему
сервису, и возвращает нормализованный ответ. При этом поведение CLI не должно
измениться.

## What Changes

- Репозиторий `agent-cli` превращается в cargo workspace: библиотека
  `crates/core` (`agentcore`, туда переезжают `src/agent/` и `src/config.rs`)
  и бинарник `crates/cli` (`agentcli` — TUI, CLI-команды, чаты).
  Публичное поведение CLI сохраняется без изменений.
- Сервис живёт в **отдельном репозитории** `/Users/egor_lyadskiy/ai/agent-sever`
  (бинарник `agentd` на `axum` + `tokio`), который подключает `agentcore` как
  внешнюю зависимость. Решение по расположению принято пользователем.
- В `agentcore` появляется модуль конвейера: трейты `InputPolicy`,
  `OutputPolicy`, `Judge`, тип `RequestContext`, `PolicyOutcome`,
  `JudgeVerdict` и структура `Pipeline`, собирающая стадии вокруг
  `Arc<dyn Agent>`. Реализации стадий сейчас — тривиальные no-op.
- HTTP-контракт версии `/v1`: `POST /v1/chat`, `GET /v1/models`,
  `GET /healthz`, `GET /readyz`, единый конверт ошибок и поле `policy`
  в успешном ответе (пустое, но присутствует с первого дня).
- Конфигурация сервиса — только переменные окружения `AGENTD_*` (плюс `PORT`).
  Сервис не читает пользовательский `~/.config/agentcli/config.toml`.
- **BREAKING** (внутри ядра, не для пользователя CLI): директория JSONL-логов
  запросов/ответов больше не выводится из `CARGO_MANIFEST_DIR`, а задаётся
  вызывающей стороной и может быть отключена; запись логов становится
  неблокирующей.
- **BREAKING** (внутри ядра): текст ошибки «API key не задан» перестаёт быть
  зашитой подсказкой команды CLI — сообщение задаёт вызывающая сторона,
  а сервис вообще падает на старте, если ключ не задан.
- Развёртывание: многостадийный `Dockerfile`, `.dockerignore`, `HEALTHCHECK`
  на `/healthz`, README сервиса с таблицей переменных окружения и примером `curl`.

Вне задачи: стриминг ответа, реальные правила политик и промпты judge,
многопользовательность и квоты, хранение диалогов на сервере, веб-интерфейс.

## Capabilities

### New Capabilities
- `agent-core`: переиспользуемое ядро (`agentcore`) — вызов модели через трейт
  `Agent`, настройки `ChatSettings`, телеметрия `MessageMeta`, настраиваемое
  и отключаемое неблокирующее логирование обмена с провайдером.
- `request-pipeline`: явный конвейер обработки запроса
  (нормализация → input policy → вызов модели → output policy → judge)
  с расширением через регистрацию стадий, без правки обработчика.
- `http-api`: сетевой контракт сервиса `agentd` — эндпоинты, форматы запроса
  и ответа, коды и конверт ошибок.
- `service-runtime`: конфигурация из окружения, аутентификация клиентов,
  лимиты (тело, конкурентность, таймауты), structured logging, `request_id`,
  graceful shutdown, упаковка в контейнер.

## Impact

- `Cargo.toml` (корневой) → манифест workspace; исходники переезжают из `src/`
  в `crates/core/src/` и `crates/cli/src/`. Пути импортов внутри CLI меняются
  с `crate::agent` / `crate::config` на `agentcore::agent` / `agentcore::config`.
- `src/agent/http.rs`: `logs_dir()`, `append_log_line()` и текст ошибки про
  отсутствующий ключ; `HttpAgent::from_config` получает параметры логирования.
- `src/main.rs`, `src/tui.rs`, `src/cli.rs`, `src/chats.rs` — только правка
  импортов и передача параметров логирования; поведение неизменно.
- Новый репозиторий `agent-sever`: крейт `agentd`, зависящий от `agentcore`.
- Новые зависимости: `axum`, `tower`, `tower-http`, `tracing`,
  `tracing-subscriber`, `tracing-appender`, `uuid` (или собственный генератор
  `request_id`), `wiremock` (dev). Ядро дополнительно получает `async-trait`
  (уже есть) для трейтов конвейера.
- Логи: путь `logs/` в репозитории перестаёт быть жёстко зашитым; для CLI
  поведение сохраняется через явную передачу того же пути.
