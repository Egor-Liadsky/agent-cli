## Purpose

Позволяет клиенту сужать операторский лимит контекстного окна сервиса
`agentd` для своих запросов через один общий настраиваемый лимит,
применяемый ко всем чатам.

## ADDED Requirements

### Requirement: Конфиг клиента хранит необязательный лимит контекста

`Config` SHALL содержать необязательное поле `max_context_tokens` — целое
положительное число токенов. Не заданное поле (значение по умолчанию)
SHALL означать, что клиент не сужает лимит контекстного окна: запросы к
сервису уходят без поля `settings.max_context_tokens`, и действует
операторский лимит `agentd` по умолчанию. Значение — общее для всех чатов
клиента: у сервиса нет постоянного хранилища для лимита конкретного чата
(значение действует только на один запрос, `POST /v1/chat`), поэтому
клиент не может настроить разный лимит для разных чатов без повторного
ввода при каждом запросе. Значение сохраняется в файле конфигурации и
переживает перезапуск клиента.

#### Scenario: Клиент без заданного лимита

- **WHEN** пользователь не задавал `max_context_tokens` в конфиге
- **THEN** запросы к сервису не содержат поле `settings.max_context_tokens`

#### Scenario: Значение сохраняется между запусками

- **WHEN** пользователь задал `max_context_tokens` и перезапустил клиент
- **THEN** значение читается из конфига и снова передаётся во всех запросах

### Requirement: Лимит контекста передаётся в запрос к сервису

Когда в конфиге клиента задан `max_context_tokens`, клиент SHALL передавать
его в поле `settings.max_context_tokens` тела `POST /v1/chat` для каждого
запроса — как разового (`ask`), так и в существующем чате (`ask_in_chat`).
Клиент MUST NOT проверять значение сам или сравнивать его с операторским
лимитом сервиса — эта проверка принадлежит `agentd`; ответ сервиса (`400
context_limit_invalid` при значении больше операторского лимита, `400
context_limit_exceeded` при истории больше эффективного лимита)
показывается пользователю как обычная ошибка запроса.

#### Scenario: Заданный лимит уходит в каждый запрос

- **WHEN** в конфиге клиента задан `max_context_tokens` равный N
- **THEN** тело каждого `POST /v1/chat` содержит `settings.max_context_tokens: N`,
  независимо от того, какой чат активен

#### Scenario: Сервис отклоняет лимит или историю

- **WHEN** сервис отвечает `400` с кодом `context_limit_invalid` или
  `context_limit_exceeded`
- **THEN** клиент показывает пользователю текст ошибки сервиса, не отправляя
  запрос повторно и не изменяя сохранённое значение лимита в конфиге

### Requirement: Лимит контекста настраивается командой и в интерактивном режиме

Клиент SHALL предоставлять команду `agentcli config context-limit` с
действиями `set <tokens>` (сохранить значение), `clear` (снять лимит) и
`show` (показать текущее значение). Интерактивный режим (TUI) SHALL
позволять посмотреть и изменить то же значение в разделе подключения
панели настроек, рядом с адресом сервиса и токеном. Пустое поле в TUI
SHALL сбрасывать лимит. Введённое значение, не являющееся положительным
целым числом, SHALL быть отклонено с понятным сообщением — командой или в
TUI, — а прежнее сохранённое значение остаётся без изменений.

#### Scenario: Команда сохраняет значение

- **WHEN** пользователь выполняет `agentcli config context-limit set 4000`
- **THEN** значение сохраняется в конфиг и используется в следующих запросах

#### Scenario: Команда снимает лимит

- **WHEN** пользователь выполняет `agentcli config context-limit clear`
- **THEN** `max_context_tokens` конфига становится не заданным

#### Scenario: Пользователь задаёт лимит в TUI

- **WHEN** пользователь вводит положительное целое число в поле лимита
  контекста раздела подключения и подтверждает настройки
- **THEN** значение сохраняется в конфиг и используется в следующих запросах

#### Scenario: Некорректный ввод

- **WHEN** пользователь передаёт нечисловое значение или ноль команде `config
  context-limit set` либо вводит их в соответствующее поле TUI
- **THEN** клиент показывает сообщение об ошибке и не изменяет сохранённое
  значение лимита
