## Why

Чаты консольного клиента живут в файлах `~/.config/agentcli/chats/*.json`, хотя
сервис `agentd` уже умеет хранить их сам: после `add-chat-storage-sqlite` у него
есть полный набор эндпоинтов `/v1/chats` и запись обмена в SQLite. Из-за этого
история и настройки чата привязаны к одной машине, а два источника правды
(файл клиента и база сервиса) расходятся при первом же обращении к сервису с
`chat_id`. Клиент должен стать тонким: показывать чаты сервиса, а не вести
своё хранилище.

## What Changes

- **BREAKING** Клиент перестаёт хранить чаты в файлах: чтение, запись и
  удаление `*.json` уходят из `crates/cli/src/chats.rs`, а список чатов,
  история сообщений и настройки чата берутся из `agentd`. В модуле остаётся
  только модель чата в памяти и форматирование для TUI.
- **BREAKING** Локальная история в `~/.config/agentcli/chats` больше не
  читается клиентом: чаты берутся только из сервиса. Автоматического
  переноса или удаления этого каталога клиент не делает — при желании
  пользователь убирает его вручную.
- Чаты обоих провайдеров хранятся в сервисе. Для `cloud` это уже даёт
  `POST /v1/chat` с `chat_id`; для `ollama` ответ по-прежнему получается прямым
  запросом к локальной модели, поэтому реплики такого чата записываются
  отдельным вызовом сервиса.
- Сервис получает эндпоинт `POST /v1/chats/{id}/messages`, дописывающий готовые
  сообщения в чат, не обращаясь к облачному провайдеру: без него история
  локальных чатов в сервис не попадает.
- Операции TUI над чатами (создание, переименование, изменение настроек,
  удаление, перенос контекста между чатами) выполняются запросами к сервису.
- При недоступном сервисе TUI запускается, показывает баннер с причиной,
  адресом сервиса и `request_id`, даёт повторить загрузку и запрещает
  создание чатов и отправку сообщений, пока список не загружен.

## Capabilities

### New Capabilities
- `client-chat-storage`: где консольный клиент берёт и как меняет чаты — только
  через `agentd`, включая поведение при недоступном сервисе и судьбу
  устаревшего локального каталога
- `chat-message-api`: контракт сервиса на дозапись готового сообщения в
  существующий чат без вызова облачного провайдера

## Impact

- `agent-cli`: файловая часть `crates/cli/src/chats.rs`; `crates/cli/src/tui.rs`
  (самый большой файл проекта, ~2100 строк) переходит с прямых обращений к
  файлам на клиент сервиса и получает состояние загрузки списка; расширение
  крейта `crates/client` (`agentclient`) методами работы с `/v1/chats`;
  зависимость `dirs` в CLI остаётся нужной только для конфига и журналов.
- `agent-sever`: новый маршрут `POST /v1/chats/{id}/messages`, DTO запроса и
  функция хранилища для дозаписи сообщений; тесты в `src/tests.rs`.
  Изменение заведено в `agent-cli`, потому что основная часть работы там, но
  реализация затрагивает и второй репозиторий — со своим коммитом, своим
  прогоном `cargo test` и порядком обновления `agentcore` из CLAUDE.md, если
  правки в ядре понадобятся.
- README обоих репозиториев: описание хранения чатов, новый эндпоинт, поведение
  клиента без сервиса.
- Пользовательские данные: локальная история чатов удаляется безвозвратно.
