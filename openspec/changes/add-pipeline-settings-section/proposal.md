## Why

Каталоги MCP-сервера `pipeline-mcp` (`pipeline_root`, `pipeline_output`)
задаются только командой `agentcli config pipeline set`: из TUI их не видно и
не поменять, хотя соседние настройки клиента (адрес сервиса, «Сводки
активности») правятся в `Ctrl+P`. Чтобы включить инструменты пайплайна или
переключить каталог поиска, приходится выходить из чата в оболочку.

## What Changes

- В меню настроек TUI (`Ctrl+P`) появляется раздел «Пайплайн» — сразу после
  «Сводок активности» — с двумя текстовыми полями:
  - «Каталог поиска» (`pipeline_root`): пусто выключает инструменты
    пайплайна;
  - «Каталог записи» (`pipeline_output`): пусто означает
    `<pipeline_root>/pipeline-out`, и этот эффективный путь виден в подсказке
    на месте пустого значения.
- Оба поля заполняются вручную или по `Ctrl+X` через системный диалог выбора
  папки (существующий механизм полей-каталогов); `Ctrl+D` очищает поле.
- `Ctrl+S` сохраняет поля в конфиг клиента, как раздел «Сводки
  активности»; пустое поле записывается как отсутствующее значение, а не
  пустая строка. Если значения не менялись, конфиг не переписывается.
- Следующий ход чата после сохранения идёт с новыми каталогами.
- README описывает раздел; строка про `Ctrl+X` больше не утверждает, что
  пути пайплайна в TUI не редактируются.

Не меняется: поля `Config` ядра, `effective_pipeline_output`, формат
`config.toml`, подкоманды `agentcli config pipeline set/show/clear` и
`agentcli pipeline run`. Отдельного флага «включено» нет: пайплайн
по-прежнему включается заданным `pipeline_root`.

## Capabilities

### New Capabilities
- `settings-pipeline-section`: раздел «Пайплайн» в настройках TUI —
  отображение, правка (вручную и системным диалогом), очистка и сохранение
  каталогов `pipeline-mcp` в конфиг клиента.

### Modified Capabilities

## Impact

- `crates/cli/src/tui.rs` — варианты `FormatField` и `SettingsSection`,
  поля `SettingsEditor`, подписи, подсказки, сохранение по `Ctrl+S`, тесты.
- `README.md` — раздел `Ctrl+P` и описание `Ctrl+X`.
- `crates/core`, зависимости и модуль `folder_picker.rs` не затрагиваются.
