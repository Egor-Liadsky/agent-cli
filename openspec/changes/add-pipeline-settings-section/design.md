## Context

Раздел «Сводки активности» в `crates/cli/src/tui.rs` уже держит настройки
клиента, а не чата: поля `activity_*` в `SettingsEditor` заполняются из
`Config` в `from_chat`, собираются `activity_values` и пишутся в конфиг
`save_activity` из ветки `Ctrl+S`. Выбор каталога системным диалогом
(`Ctrl+X`) сделан общим механизмом: `FormatField::is_directory` отмечает
поле, `AppState::folder_pick` ставит запрос, `pick_folder_for_field` в
`run_app` открывает диалог, `SettingsEditor::directory_value_mut` указывает,
куда писать итог. `send_message` читает каталоги пайплайна из `state.config`
на каждом ходе, а процесс `pipeline-mcp` живёт один ход.

Ограничения: `crates/core` не меняется, новых зависимостей и модулей нет,
`folder_picker.rs` не меняется.

## Goals / Non-Goals

**Goals:**
- Раздел «Пайплайн» по образцу «Сводок активности» с двумя полями-каталогами.
- Эффективный каталог записи виден до сохранения.

**Non-Goals:**
- Флаг «включено», проверка существования каталогов при сохранении,
  запуск цепочки из настроек.

## Decisions

**Место раздела — сразу после «Сводок активности».** Оба раздела — настройки
клиента для MCP-серверов, а не параметры чата; соседство подсказывает, что
они общие для всех чатов. Альтернатива — поля внутри «Инструментов» —
смешала бы параметры чата (`git_*` в `ChatSettings`, уходят на сервис) с
параметрами конфига, и `Ctrl+S` сохранял бы их в разные места без видимой
границы.

**Нет флага «включено».** Ядро уже решает это `Config::pipeline_active` по
заданному `pipeline_root`, а `agentcli config pipeline clear` выключает
пайплайн очисткой. Переключатель в TUI потребовал бы нового поля конфига
(запрещено) или жил бы только в редакторе и расходился с CLI. Поэтому
«пусто — выключено» подписано в подсказке поля.

**Сохранение в конфиг по `Ctrl+S`, как `save_activity`.** Поля
превращаются в `PipelineValues` (`non_empty`: пустая строка → `None`), и
`save_pipeline` пишет конфиг, только если значения отличаются от текущих, —
так открытие и закрытие настроек не трогает файл. После сохранения ничего
перезапускать не нужно: следующий ход берёт каталоги из `state.config`.
Запись файла вынесена параметром (`save_pipeline_with(state, values, save)`),
потому что `Config::save` пишет в настоящий каталог конфигов ОС и путь не
переопределяется без правки ядра; тест подставляет запись-заглушку и не
трогает конфиг пользователя.

**Подсказка каталога записи считается ядром.** Для пустого поля подсказка
строится через `Config::effective_pipeline_output` на временном `Config` с
текущим значением поля «Каталог поиска», а не повторяет правило склейки
пути в TUI, — так подсказка не разойдётся с тем, что увидит `send_message`.

**`Ctrl+X` и `Ctrl+D` без нового кода обработки.** Оба поля добавлены в
`is_directory` и `directory_value_mut`, а `Ctrl+D` на текстовом поле уже
очищает значение через `field_value_mut`.

## Risks / Trade-offs

- [Опечатка в пути сохраняется без проверки] → ошибка видна в первом ходе,
  как и у `config pipeline set`; `Ctrl+X` снижает шанс опечатки.
- [Одновременная правка конфига командой из другого терминала
  перезаписывается при `Ctrl+S`] → так же ведут себя остальные разделы
  конфига; запись происходит только при изменении полей раздела.
