## Context

`render_pane` (`tui.rs:2123`) делит панель чата на заголовок
(`render_pane_title`), историю (`render_history`) и поле ввода
(`render_input`, `tui.rs:2614`) через вертикальный `Layout`. Сейчас у
`render_input` нет отдельной строки телеметрии — только рамка с текстом
ввода. Всё необходимое для отображения токенов уже написано и лежит рядом
без вызовов: `TokenTotals`, `TokenTotals::from_meta`, `TokenTotals::add`,
`token_counters`, `meta_token_summary`, `chat_token_totals` (`tui.rs:2337-2415`).
См. `proposal.md` — «Why» — за объяснением, почему это доделка, а не новая
функциональность с нуля.

## Goals / Non-Goals

**Goals:**
- Вывести под историей чата постоянную строку с телеметрией последнего
  обмена и отдельно — накопительный итог по чату.
- Переиспользовать существующие `TokenTotals`/`token_counters` без
  переписывания формата счётчиков.

**Non-Goals:**
- Не меняется формат `meta_summary` в шапке сообщения (модель + время) —
  токены туда не возвращаются.
- Не добавляется постоянное персистентное хранение агрегатов на клиенте:
  итог по чату каждый раз пересчитывается из уже загруженных `messages`.
- Не меняется протокол `agent-sever` — данные уже в текущем формате ответа.

## Decisions

- **Место строки — в `render_input`, отдельной строкой над рамкой ввода,
  а не внутри `render_pane_title`.** Заголовок панели общий на весь чат
  (название, модель), а телеметрия обмена меняется после каждого ответа;
  так строка токенов физически внизу, как просит пользователь, и не
  требует перекомпоновки `render_pane_title`/`render_history`.
- **Одна строка на две части: `Обмен: …` и `Чат: …` через разделитель,**
  а не два раздельных виджета. Высота панели ввода и так ограничена;
  единая строка со сложением через `TokenTotals::add` дешевле по месту, чем
  двухстрочный блок, и обе части используют один и тот же `token_counters`.
- **Источник данных для «Обмен» — `meta` последнего сообщения ассистента**
  (`state.chats[chat_index].messages.iter().rev().find(|m| m.role ==
  Role::Assistant)`), а не последнее сообщение вообще: если пользователь
  только что отправил вопрос и ответ ещё не пришёл, строка показывает
  телеметрию предыдущего обмена, а не пусто/устаревшее сообщение
  пользователя без `meta`.
- **Источник для «Чат» — существующий `chat_token_totals(&messages)`**,
  вызываемый каждый рендер по уже загрученным в память сообщениям; отдельного
  кэша не заводится, т.к. список сообщений в чате обычно короткий и рендер
  TUI и так идёт по всей истории на каждый кадр (`render_history`).
- **Пустой чат/чат без телеметрии — строка не рисуется вовсе** (высота
  layout `render_input` под неё не выделяется), а не рисуется с прочерками:
  так область ввода не дёргается визуально между «есть строка» и «строка из
  прочерков».

## Risks / Trade-offs

- [Высота панели ввода уменьшится на одну строку при появлении телеметрии,
  что может подвинуть текст, который печатает пользователь] → строка
  телеметрии рисуется только когда есть что показать, т.е. точка
  «просадки» высоты — один раз, сразу после первого ответа ассистента в
  чате, не на каждый кадр.
- [`chat_token_totals` пересчитывает сумму по всем сообщениям на каждый
  кадр рендера] → приемлемо: то же самое уже делает `render_history» для
  той же истории каждый кадр; отдельной оптимизации не требуется, пока не
  появятся данные о деградации FPS на реальных чатах.
