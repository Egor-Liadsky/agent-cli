## Purpose

Конфигурация консольного клиента в части подключения: адрес сервиса `agentd`,
клиентский токен и связанные команды. Место для ключа облачного провайдера в
конфиге клиента отсутствует.

## ADDED Requirements

### Requirement: Конфиг клиента хранит адрес сервиса и токен

Конфиг клиента SHALL содержать `server_url` — адрес сервиса `agentd` со
значением по умолчанию `http://127.0.0.1:8080` — и `client_token` для
заголовка `Authorization`. Пустой токен допустим. Полей `api_key` и `base_url`
облачного провайдера в конфиге клиента больше нет.

#### Scenario: Значение по умолчанию

- **WHEN** пользователь не задавал адрес сервиса
- **THEN** клиент обращается к `http://127.0.0.1:8080`

#### Scenario: Показ конфигурации

- **WHEN** пользователь выполняет `agentcli config show`
- **THEN** вывод содержит `server_url` и маскированный клиентский токен и не
  упоминает ключ облачного провайдера

### Requirement: Команды настройки подключения

Клиент SHALL предоставлять `config set-token` для сохранения клиентского токена
и `config set-url` для адреса сервиса. Команда `config set-key` SHALL быть
удалена. Команды настройки Ollama (`ollama models`, `ollama use`,
`ollama set-url`) SHALL сохранить нынешнее поведение.

#### Scenario: Сохранение токена

- **WHEN** пользователь выполняет `agentcli config set-token <значение>`
- **THEN** токен сохраняется в конфиг и применяется к следующим запросам, а в
  выводе показывается маскированным

#### Scenario: Команда ключа удалена

- **WHEN** пользователь выполняет `agentcli config set-key <значение>`
- **THEN** клиент сообщает о неизвестной команде и не сохраняет ключ

### Requirement: Список моделей берётся у сервиса

Команда `config models` SHALL получать список моделей запросом
`GET {server_url}/v1/models`, а не из встроенного списка. При недоступном
сервисе команда MUST сообщать понятную ошибку с адресом сервиса, а не печатать
пустой список.

#### Scenario: Сервис доступен

- **WHEN** пользователь выполняет `agentcli config models` при работающем
  сервисе
- **THEN** печатается список моделей, разрешённых сервисом

#### Scenario: Сервис недоступен

- **WHEN** сервис по адресу `server_url` не отвечает
- **THEN** команда завершается ошибкой с указанием адреса сервиса и не печатает
  пустой список как успешный результат

### Requirement: Устаревший конфиг читается без ошибки

Конфиг с полями `api_key` и `base_url`, оставшимися от прежней схемы, SHALL
читаться без ошибки: неизвестные поля игнорируются. При их наличии клиент SHALL
один раз за запуск напечатать предупреждение, что ключ провайдера больше не
используется и его следует убрать из файла. Файл конфигурации MUST NOT
перезаписываться без явного действия пользователя.

#### Scenario: Запуск со старым конфигом

- **WHEN** пользователь запускает клиент с конфигом, содержащим `api_key` и
  `base_url`
- **THEN** клиент работает штатно, один раз печатает предупреждение об
  устаревших полях и оставляет файл нетронутым

### Requirement: Раздел подключения в интерактивном режиме

Раздел «Подключение» интерактивного режима для облачного чата SHALL содержать
адрес сервиса, клиентский токен и модель вместо базового URL и ключа
провайдера. Раздел для Ollama SHALL остаться прежним. Изменённые адрес и токен
SHALL сохраняться в глобальный конфиг и применяться к следующим запросам без
перезапуска клиента.

#### Scenario: Правка адреса и токена

- **WHEN** пользователь открывает раздел «Подключение» в облачном чате,
  изменяет адрес сервиса и токен и сохраняет настройки
- **THEN** значения попадают в глобальный конфиг и следующий запрос уходит на
  новый адрес с новым токеном без перезапуска

#### Scenario: Раздел Ollama не изменился

- **WHEN** пользователь открывает раздел «Подключение» в чате с провайдером
  `ollama`
- **THEN** состав полей раздела остаётся прежним
